# Audit: `ane/h15` vs `ane/h18` — register offsets, struct fields, magic constants

Row Q-88 (ANE): feeds the M3 diagnostic work. Research only — no code, no machine runs.

## Sources and method

- Corpus: `research/oracles/h15/*.json` (316 records) and `research/oracles/h18/*.json` (330 records), matched by `case`. 316 paired cases; h18 adds 14 named-tensor cases (`*_names_*`, `name_edge_*`) the h15 corpus does not carry; no h15-only cases.
- Comparison: per case, `task_descriptors[0].blocks.<block>.words` are word-diffed by offset, and `records[].address` sets are set-diffed. 259 pairs carry a task descriptor; 57 pairs (the `*_constant_inline` shapes) do not — those two compilers emit **byte-identical hwx blobs** (57/57 identical `hwx_sha256`), so only the program-descriptor level differs for them (and only in `compiler.command`/`target`).
- Tool: a one-pass Python diff of the JSON trees; every row below names its source as the pair of oracle files plus the JSON path.
- Author family check: produced by wB4 (zai family) reviewing data produced by the Apple compiler oracle (no lane author).

## Notes on specific magic constants

- `tile_dma_dst 0x05100 = 0x01000031` (h15) vs `0x01000021` (h18): the constant appears in every one of the 203 pairs that write it, always differing by bit 4 (0x10). Candidate dst-engine mode bit.
- `tile_dma_src 0x04d68/0x04d6c = 0x01002031` (h15) vs `tile_dma_dst 0x05140 = 0xf0003211` (h18): the packed word-pairs are generation-specific encodings, not value-noise (0x04d68 appears in 259/259 pairs with the identical h15 constant).
- `trailing_words[5]`: `0x47` (h15) vs `0x4f` (h18) — generation-tag-looking word in the program tail.
- `trailing_words[14]`: `0x888` (h15) vs `0x898` (h18) — a second generation-tag-shaped word.
- `trailing_words[26]`: `0x9` (h15) vs `0x7` (h18); `trailing_words[22]`: `0x5` vs `0x4`; `trailing_words[24]`: `0x1` vs `0x2` — small-id words that differ constantly.
- `trailing_words[28]`: `0x9` (h15) vs `0x461c4000` (h18) — h18 packs a float-looking word where h15 packs a small id; the h15 `trailing_words[30]` ASCII `main` word moves to `trailing_words[34]` in h18.

## What this table feeds

The M3 diagnostic work (H15-family diagnostics against an H18 machine) needs this mapping before any
register-offset assumption transfers. Every delta row above is one place an h15-informed read or write
would land on the wrong offset, the wrong word, or a constant the h18 engine does not use.

## Sources per row

Every row's source is the pair `research/oracles/h15/<case>.json` and `research/oracles/h18/<case>.json`
at the JSON path named in the row (block → offset for word rows; program_descriptor field for S-rows),
plus `tools/verdict.sh`-shaped review by wB4 (zai/glm-5.3-flash) of data emitted by the Apple compiler
oracle — no lane-authored code is under review here.
