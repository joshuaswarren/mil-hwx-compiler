## Cause

`batchedMatmulParse` requires `batch > 1`. Rank-4 leading extents `1×1` give B=1, so the parse returns No. The op never reaches `kBatchedTasks` / `apple-parity-batched-matmul`.

The runtime 2D fallback then needs `supportsMatmulParity({375,1024,128,tx=0,ty=0,runtime})`. That key is not in the single-batch envelope. Reject, no programs.

This is not the const-W 1875-program matvec path. Both operands are runtime, so the planner does not slice K=1024 into two 512-matvecs.

A frontend rewrite that only inserts a unit batch axis is not justified. B∈{2,4,8,16} still would not help: `kBatchedTasks` is the attention geometries `(375,128,375)`, `(375,128,749)`, `(375,375,128)`, not `(375,1024,128)`.

Did not emit 1875 or 15000 programs. Did not add an overlay module.

Named miss: `h13.matmul-outside-envelope` for rank-4 B=1 `(375,1024,128)` runtime.
